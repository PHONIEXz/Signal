# Signal visual direction

Signal is a working desk for creators looking for the pattern in their own account data. The interface should feel like a considered editorial report paired with a dependable analytics tool.

## The sequence for new pages

1. **Start with the job.** Write one sentence about the decision the page helps someone make. Identify the real data, missing-data states and primary action before arranging cards.
2. **Choose a reference for structure.** Look for editorial publications, financial research tools and data products with strong hierarchy. Translate their spacing, typography and information order; do not copy a screenshot or invent unsupported product claims.
3. **Sketch the hierarchy.** Lead with a clear title and context. Put important data or the next action first. Use a rule, a number, or a simple table before reaching for another card.
4. **Apply Signal's system.** Warm paper, deep navy, one restrained amber accent, serif display headings, plain sans-serif controls, mono labels. Use `PageIntro`, `.eyebrow`, `.section-index`, `.editorial-panel`, and `.interactive-card` where appropriate.
5. **Build real states.** Check empty, loading, partial-data, error, mobile and dark appearances. Label examples explicitly. Keep platform limitations visible rather than using placeholder numbers.
6. **Polish after the structure works.** Motion should explain an interaction or state. Avoid decorative glow, identical grids of cards, animated ornaments and generic slogans.

## Visual rules

- Layout: one dominant section per page, generous reading space, thin dividers and occasional asymmetric columns. Content determines the layout.
- Type: display serif for editorial headings and large measures; body sans for UI; mono for section labels and small indices. Preserve readable line lengths.
- Color: navy carries trust and actions; amber calls attention to a moment; green means a real connected or successful state. Never use color alone for status.
- Surfaces: white on warm paper, with borders for grouping. Static panels do not rise on hover; interactive panels may.
- Data: show the source, time, sample and unavailable state whenever the distinction matters. Never imply example visuals are a live account.
- Mobile: stack columns intentionally, keep actions reachable and ensure no horizontal overflow. Dark mode needs the same hierarchy and contrast.

The landing preview is an explicitly illustrative view. Product screens should use actual account state and make missing information understandable.
